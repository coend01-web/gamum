# CAMUM 플랫폼 공통 UI — v1 검토 시안

**개발 브랜치:** `design/platform-shell-v1` · **기준:** 공개 v0.2 유지. **상태:** 실제 운영/DB와 무관한 시각·정보구조 프로토타입.

## 목표
- 단계를 추가하더라도 로고, 계정·서랍, 네 가지 피정 탐색, 검색·카드 규칙이 움직이지 않는 **안정적인 플랫폼 쉘**을 먼저 확정.
- 갓피플: 재방문할 만한 콘텐츠·큐레이션 / 템플스테이: 실제 피정 정보 탐색 / Apple: 시각적 위계·정밀한 정보·조작의 직관성. 세 브랜드의 사이트를 복제하지 않는다.
- '따뜻한 피정 안내문'처럼 보이는 한계를 벗어나 **프리미엄·신뢰·절제·접근성**을 동시에 확보.

## 진화할 서비스 영역
1. 1단계: 머뭄·피정 — **나를/주제로/날짜로/장소로 찾는 네 입구 동등하게 유지**. 오늘 1분 머뭄 처음부터 열려 있으며 같은 위치. 실제 신청은 수도회 공식 신청처로 연결.
2. 2단계: 생활성가·찬양사도 — 아티스트/찬양팀·공연 날짜/지역 중심, 독립 카탈로그.
3. 3단계: 신부님·강사 — 사목자/강사 프로필과 강의 주제·행사 연결. 공식 확인된 경력·동의 정보.
4. 4단계: 가뭄 마켓 — 성물·가톨릭 출판물·굿즈의 다판매자 시장. 검색·입점·주문/배송/환불은 별도 운영 기능.
5. 장기: 다국어·아시아 지역 확대, 최종 비전 CAMUM 빌리지. 메인 탐색에 별도 시설사업을 즉시 노출하지 않음.

## 정보구조 불변 규칙
- 가뭄 로고/홈, 상단 공통 유틸리티(서랍/계정·안내), 서비스영역 탐색 영역을 분리.
- **메뉴 확장 때 기존 머뭄·피정 메뉴를 왼쪽 첫 위치에 고정.** 사용자가 배운 탐색 위치·용어·동작을 바꾸지 않는다.
- 미래 기능을 현재 운영되는 듯 '준비중 메뉴'로 노출하지 않는다. 검토 시안에서만 `stage-select`로 미리보기 가능.
- 피정 전용 네 입구를 마켓/강의/공연 구분 없는 범용 검색으로 합쳐서 없애지 않는다. 통합 검색은 후속으로 추가하되 결과 유형을 분명하게 구분.
- 공통 타이포그래피, 컬러, 카드 구조, 필터, 버튼, 저장(서랍) 표현을 하나의 디자인 시스템으로 유지.
- 머뭄 콘텐츠와 광고(특히 성지순례 여행사·상품)를 피정 추천에 섞지 않는다. 스폰서·제휴 콘텐츠는 명확한 표시와 별도 위치.
- 수도회 관리자 시스템은 이용자 인터페이스와 별도 경로에서 운영. 로그인/관리번호는 절대로 홈페이지 메인 탐색 흐름을 방해하지 않음.

## 현재 v0.2 대비 개선할 사항
- 민트·아이보리 톤을 화면 전반에 반복하지 않고, 오프화이트·차콜·딥그린·소량의 골드로 명확한 명도 차.
- 시제품 같은 그라데이션 썸네일은 **실제 사진 사용 허가 전까지만** placeholder로 표시. 실제 피정이 아니면 반드시 '시연 데이터' 표기.
- 모바일에서는 첫 화면의 과잉 헤더를 줄이되 핵심 기능을 숨기지 않음. 화면 폭 360·390·768·1280에서 검증.
- 작은 연녹색 글자, 큰 테두리·무작위 둥근 모서리 반복 지양. 44px 이상 클릭 대상과 선명한 focus, reduced motion 반영.
- '시연판'은 기존 v0.2에서 계속 고지하며 실제 출시 전에만 조정.

## 시안 실행
브라우저에서 `design/platform-shell.html`을 열면 됩니다. JS는 개발 검토용 **확장 단계 선택기**만 제공. 메뉴 변화 시 사용자의 현재 위치를 유지합니다.
- `?stage=1`: 피정만
- `?stage=2`: 피정+생활성가
- `?stage=3`: +신부님·강사
- `?stage=4`: +가뭄 마켓
- 네 가지 피정 입구와 기존 1분 머뭄 링크는 **상대 경로로 기존 사이트에 연결**되며 프로토타입 자체에서 추천/결제/등록 구현이 완료됐다는 뜻은 아닙니다.
- 이 시안의 기관명, 피정 제목, 모든 일정·카드는 설명용 가상 예시입니다.
- GitHub Pages의 공개 `main`은 변경하지 않음. `design/platform-shell-v1` 코드를 검토·승인받은 뒤 별도 통합 작업을 수행.

## Codex에 인계
현재 로컬 v0.21 작업과 충돌하지 않도록 **별도 Git worktree 또는 별도 checkout**에서 `design/platform-shell-v1`을 열 것. 사용자의 승인 전 `main`에 병합하거나 Supabase 배포하지 말 것. 시안은 별도 미리보기만 제공하고, 실데이터 연결은 v0.21 운영 테스트를 통과한 뒤 계획할 것.

## 검사
`node --check design/platform-shell.js`, `node tests/platform-shell.test.mjs`. 시각 QA는 실제 Chrome/Safari PC·모바일에서 별도 수행 필요. 코드 검사 성공만으로 디자인 사용성을 검증했다고 주장하지 말 것.
