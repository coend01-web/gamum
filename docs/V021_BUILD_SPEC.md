# CAMUM v0.21 — 수도회 실제 운영 시스템 개발 기준
작성일: 2026-11-08
상태: **개발 시작**. 아직 실제 로그인·DB·기관 가입·정식 운영 배포가 되지 않았음.
공개 main은 이미 배포된 v0.2이며 변경 금지. 개발 브랜치: `feature/v0.21-convent-ops`.

## 목표
수도회 담당자가 휴대전화와 PC에서 로그인하고, 자신이 운영하는 **모든 피정 프로그램**과 반복 **회차**를 등록·수정·조기마감·공개한다. 승인된 실제 피정은 신자용 네 가지 탐색과 10문항 추천에 연결돼 공식 신청/문의 링크로 이동한다. 수도회 이용 및 홍보 수수료는 0원, 각 기관이 기존 신청·입금·환불 방식 유지.

## 절대로 잃지 않을 기능
1. 나를/주제로/날짜로/장소로 찾는 네 가지 동등한 입구.
2. CAMUM 일상형 10문항(고정 신앙 유형 검사 금지), 결과에서 **실제 피정 추천 먼저** → 성경·성인·묵상·기도.
3. '오늘, 1분 머뭄'은 기본 펼침. 나의 머뭄 서랍, 기존 수도회 시연, QR 후기·모집 시연 보존.
4. 가상과 실제 데이터 완전 구분. 허가되지 않은 수도회 사진·연락처 무단 게시 금지. 초기 수엘 캐릭터 제외.
5. 성지순례 광고와 일반 피정 추천 결과 혼합 금지.

## 핵심 테이블과 책임
- `organizations`: 소속 수도회/단체, 검증 상태 pending/approved/rejected/suspended. 기관 자체 승인 금지.
- `organization_credentials`: 기관당 고유 관리번호 하나와 공유 관리자 비밀번호 하나, 기관 계정 상태·비밀번호 변경·검증된 복구 절차. 비밀번호 원문 저장 금지, 인증 제공자 이용 또는 강한 해시·서버 검증. 기관별 로그인 세션 분리.
- `retreat_houses`: 기관이 운영하는 피정의 집 여러 곳, 위치·공식 연락처.
- `retreat_programs`: 반복 가능한 프로그램, 다중 영성/주제/진행 방식 태그, 대상 자격, 공식 신청처, 공개 상태.
- `retreat_sessions`: 개별 회차와 실제 날짜/모집일·마감일·참가비·정원·모집/조기마감·신청 링크·최종 확인 시각.
프로그램 한 건에 회차 여러 건. 반복 일정/복제/일괄 업로드. 일괄 등록은 **파일 검사→미리보기→오류 수정→승인 저장**. 단순 한 프로그램 시범 등록으로 축소 금지.

## 참가 조건과 모집 표시
프로그램별 대상·연령·동행·선행과정이 확인되지 않으면 승인된 정보로 속여 게시하지 않는다. 회차별 모집 예정/접수 중/대기/일시중단/조기마감/취소/종료를 구분. 좌석 잔여 수는 근거가 있을 때만 공개하고, 실시간 갱신이라고 허위 표시하지 않는다. 연락처 또는 공식 신청 페이지가 없으면 공개 불가.

## 아키텍처
정적 GitHub Pages(v0.2)는 그대로 유지하고, 새로운 실운영용 인증과 DB가 필요하다. 초기 후보: **Supabase Auth/PostgreSQL/RLS + 필요한 서버 함수**. 웹에 Supabase URL과 publishable key만 노출 가능; secret key/DB 비밀번호/관리자 키는 서버에만. 기관 승인, 초대, 관리 작업은 서버 측 권한 검사 필수. RLS로 기관 A 담당자가 기관 B의 초안/회차를 읽거나 바꾸지 못해야 한다. 실제 프로젝트 계정·도메인·DB 연결은 사용자 명시적 설정이 필요. 별도 개발 환경에서 먼저 구현하고 검증.

## 개발 순서
1. 기존 main 백업, 테스트, v0.21 브랜치 검증.
2. 실제 DB 스키마/인증/RLS. 운영자 승인·기관별 관리번호/비밀번호 발급 및 복구 플로우와 기관 간 접근 차단 테스트.
3. 수도회 전체 프로그램 등록/수정/복제/다중 회차/반복·CSV 업로드/마감/공개. 등록·수정 내용을 서버에 저장.
4. 공개 카탈로그와 네 가지 탐색·10문항 추천 실데이터 연동(가상 분리).
5. 공식 신청처, QR 후기/현장 인증/모집 상태/알림 등 운영 기능을 안전하게 연결.
6. 백업/복구, PC·모바일, 개인정보/권한, 접근성, 실제 수도회 담당자 운영 E2E 테스트.
7. 공개 배포 전 **사용자 별도 승인**. v0.21이 실제 운영 가능해야만 v0.3으로 진행.

## v0.21 합격 시나리오
- 승인 안 된 기관은 프로그램 초안을 저장할 수 있지만 일반 신자에게 공개 못함.
- A 수도회 직원은 B 수도회의 비공개 피정을 읽기/수정/게시/마감 불가.
- 수도회 1곳이 다수 프로그램과 수십 회차를 생성·중복 방지·수정하고 일괄 업로드 가능.
- 한 회차를 조기 마감해도 다른 회차는 그대로. 날짜/정원/비용·모집 상태 계산 정확.
- 인증된 프로그램만 장소·날짜·주제·10문항 결과에 반영. 실제 공식 신청 링크·연락처 확인.
- 0~3개 추천, 지역/기간/대상/비용 필터, 자격 모호하면 재확인 요청.
- 브라우저 새로고침/다른 기기에서 저장 유지, PC/모바일 360/390/768/1280px 검증.
- 기존 v0.2 기능 회귀 테스트, 안전한 QR 후기·알림·접근 제어·운영 데이터 백업/복구.
- 실제 신청/입금 처리는 각 수도회에서만 수행.

## Codex 수행 규칙
이 문서를 전체 읽은 뒤 **아키텍처 설명만 하지 말고** 실제 코드/테스트를 작성해 커밋할 것. 사용자는 초보자이므로 클라우드 서비스 개설/설정은 클릭 위치를 구체적으로 1단계씩 안내. 비밀 키를 대화에 붙여넣도록 요구 금지. 실제 DB 연결이 없으면 임시 데이터로 테스트하면서 '실서비스 완료'라고 말하지 말 것. 완료 보고에는 커밋·실행 URL·RLS 테스트·실제 로그인/등록/공개 여부·남은 일·필요한 사용자 조치 포함.

## 확정된 수도회 로그인 운영 정책 (2026-11-08, 사용자 직접 수정)

**중요: 기관마다 고유 관리번호 하나 + 공유 관리자 비밀번호 하나. 담당자별 개별 계정 가입은 필수로 요구하지 않는다.** 이전 문서의 개인별 계정 중심 제안을 이 정책으로 대체한다.

### 기본 원칙
- 가뭄 중앙관리자가 승인한 수도회/운영기관마다 변경되지 않는 고유 관리번호 1개 발급. 예: `CAM-0001`. 이 번호는 신분 구분용이며 비밀이 아님.
- 기관별 비밀번호 1개를 공유하며, 담당자 여러 명이 동일 기관 계정에 접속해 해당 기관의 모든 피정·회차·시설을 관리할 수 있다.
- 담당 수녀님/수사님/직원이 교체되더라도 **기관 관리번호 및 기존 등록된 자료는 영구 유지**한다. 새로운 담당자는 해당 기관 계정을 인계받는다.
- 담당자 변경/퇴임으로 접근을 차단해야 할 때는 기관 비밀번호를 바꾸고, 필요하면 기존 모든 로그인 기기/세션을 무효화한다. **비밀번호를 바꾸지 않으면 이전 담당자도 접근 가능**하다는 점을 관리 화면과 인수인계 문서에 명확히 표시한다.
- 비밀번호 분실 시 기관의 기존 공식 연락처 등을 통해 **중앙 관리자에 의한 기관 확인 후** 재설정. 관리번호만 안다고 초기화할 수 없도록 한다.
- 수도회 관리번호는 DB UNIQUE + 서버 발급. 이름/담당자가 바뀌어도 고정. 한 기관 아래 여러 피정의 집/프로그램/회차.
- 수도회별 계정은 별도로 로그인한 다른 기관의 비공개 내용을 읽거나 쓰지 못하게 DB RLS 및 서버 측 토큰/세션 정책으로 차단한다.
- 사용자에게 수백 개 비밀번호를 직접 생성·관리하게 하지 않는다. 계정 발급·비밀번호 초기설정·회복 절차를 관리자 화면에 제공한다.
- 비밀번호는 화면·GitHub·로그·DB에 원문 저장/출력 금지. 안전한 인증 시스템을 사용하고, 로그인 시도 횟수 제한·잠금·이상접속 알림 적용. 공유계정의 개인정보·결제정보 직접 관리 범위는 최소화.
- 플랫폼 **중앙관리자**는 수도회 공유 계정과 반드시 분리된 강한 인증 및 MFA 사용. 중앙관리자가 수도회 비밀번호 원문을 보지 않고도 재설정 가능해야 한다.
- 공용 기관 계정이므로 **어느 개인이 수정했는지는 확인할 수 없음**을 인정한다. 기관 차원에서 수정 일시와 변경 내역·기기/세션 식별자는 개인정보 최소 수집 원칙을 지켜 기록한다.
- 필요하면 나중에 개인별 담당자 로그인 옵션을 **추가 가능하도록** 내부 구조를 설계하되 v0.21 필수 사용 흐름에 넣지 않는다.

### 실제 사용자 로그인 화면
```
수도회 관리자 로그인
[기관 관리번호: CAM-0001]
[비밀번호: ••••••••]
[로그인]
[비밀번호를 잊으셨나요?]
```

### 통과 조건
1. A 기관 계정으로 로그인 → A 기관 프로그램과 회차 전체 등록·수정 가능.
2. B 기관 비공개 자료 접근 불가, 기관 관리번호 추측만으로 접근 불가.
3. 담당자 교체해도 기존 기관 번호/프로그램/회차/QR 후기 모두 유지.
4. 비밀번호 변경 후 옛 비밀번호 로그인 거절, 기존 세션 무효화.
5. 비밀번호 재설정은 기관 확인 없이는 불가.
6. 기관 승인·정지·중복 ID 발급·수백 개 기관 성능·로그인 제한 검증.
7. 새 시설을 추가하더라도 동일 기관 관리번호에서 함께 관리.
