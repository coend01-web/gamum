# CAMUM v0.21 — CBCK 전국 수도회·수녀회·피정의 집 사전 등록 지침

**기준: 2026-11-09 한국 천주교 주소록 자동 전수 점검. 운영 계정은 아직 미발급.**

## 1. 공식 출처와 목록 범위
- CBCK 남자 축성생활회·사도생활단 주소록: 224 등재 기록.
- CBCK 여자 축성생활회·사도생활단 주소록: 500 등재 기록.
- CBCK 피정·기도의 집 주소록: 190 등재 기록.
- 총 914 등재 기록. 수도회 본부/관구 후보로 별도 분류된 기록은 남자 50 + 여자 112 = **162 후보**다. 이 기록은 앞의 724건에 포함되어 있으므로 총계에 더하지 않는다.
- 온라인 주소록은 지속 업데이트되므로 날짜별 건수는 달라진다.
- URL: https://directory.cbck.or.kr/OnlineAddress/Default.aspx
- 보조 교차 확인: https://missa.cbck.or.kr/Retreat (2026-01-26 게시자 수정일). CBCK 디렉터리와 일치하지 않는 기록은 수동 검토한다.
- CBCK 공식 데이터의 전면 재게시·재사용 조건은 CBCK와 협의한다. 플랫폼에 CBCK 공식 인증·제휴 표기를 허가 없이 사용하지 않는다.

## 2. 세 가지를 절대 혼동하지 않는다
1. **본부·운영 주체** — 실제 수도회·수녀회·관구·교구·운영단체. 중앙 검증 후 관리번호 `CAM-000001` 형태의 기관 계정 **하나**. 한 기관이 여러 피정의 집 운영 가능.
2. **분원·수도원·지역 공동체** — CBCK에 개별 기록되어 있어도 대체로 별도 기관관리자 계정을 발급하지 않음. 소속·법적 운영 주체 확인 후 연결.
3. **피정·기도의 집** — 별도 시설번호 `CAM-H-000001`. 부모 기관의 소속 시설. 교구 운영 시설도 있으므로 수도회에 함부로 자동 귀속시키지 않는다.

## 3. 이미 개발 브랜치에서 준비한 코드
- `scripts/prepare_cbck_catalog.py` : 공식 주소록 5개 분류를 마지막 페이지까지 읽고 정확한 총계를 검증. 남/여 전체, 피정의 집, 남/여 본부 후보. 중복되는 목록 외 링크 3건을 필터. 기간별 재실행 시 기존 후보번호 보존.
- `scripts/export_cbck_staging_sql.py` : 검수용 SQL 출력. **공개 테이블·로그인 계정에 직접 등록하지 않는다.**
- `supabase/migrations/202611090003_cbck_staging.sql` : 접근 차단된 비공개 `camum_private.cbck_directory_staging` 스키마 준비.
- `.github/workflows/cbck-directory-audit.yml` : GitHub Actions에서 공식 출처 전수 조회·SQL 생성 검사를 자동 실행. 결과를 일시적 다운로드 자료로 제공하며 공개 홈페이지에는 노출하지 않음.
- `private/cbck/` 경로는 Git에서 무조건 제외. CSV·SQL·주소록 작업자료를 공개 저장소에 커밋 금지.

## 4. 진행 상태
- 공식 목록 자동 전수 확인 **완료**: 224/224, 500/500, 190/190, 본부 50/50 및 112/112. 검증 통과 로그는 GitHub Actions 참조.
- 예비기관 162개 + 시설 190개에 **관리번호/시설번호 예약 후보 생성 로직** 준비. 아직 기관 소속과 중복 검증 전이며 실계정은 0개.
- **2026-11-10 개발 프로젝트 실제 적용 완료.** 0001~0004, 기관 후보 162개·시설 후보 190개를 비공개 staging에 등록하고 실제 DB 조회·RLS 검사를 통과했다. 운영 계정·공용 비밀번호는 발급하지 않았다.
- 실제 기관별 공용 비밀번호는 없음. 수도회 본인이 등록신청→중앙관리자 확인→유효기간 제한 초대/비밀번호 최초 설정→기관 계정 활성화 순서.

## 5. Mac mini Codex에서 진행할 작업
```bash
git switch feature/v0.21-convent-ops
python3 -m pip install beautifulsoup4
python3 scripts/prepare_cbck_catalog.py
python3 scripts/export_cbck_staging_sql.py
```
Python 환경 문제가 있으면 Codex가 안전한 가상환경을 만들어 실행한다. 출력: `private/cbck/organizations_pending.csv`, `retreat_houses_pending.csv`, `cbck_all_records.csv`, `report.json`, `cbck_staging_review_ONLY.sql`.

**정식 Supabase 연결 전 보안 절차**:
1. CBCK 명부 활용 허가/표시 범위 확인. 후보를 공개 서비스에 무단 게시하지 않음.
2. 기관의 본부/관구 중복과 시설 소속 관계 검토, '본부 후보'가 자동으로 수도회 실계정이 되지 않도록 함.
3. Supabase 개발 프로젝트에 마이그레이션 0001→0002→0003→0004 적용·권한 검사(사용자 승인 및 프로젝트 식별 필요).
4. 로컬에서 만든 SQL을 **비공개 staging**에만 적용. 개인정보·비밀번호 생성 없음.
5. 중앙관리자 검증 후 승인한 기관만 `organizations`로 등록. 예약된 번호가 실운영 DB의 `next_number` 생성기와 충돌하지 않도록 시퀀스 동기화 테스트. 변경 시 기존 예약 번호 불변 유지.
6. 각 수도회 신청·인수인계 후 기관별 공용 비밀번호를 안전한 인증 절차로 설정. 기존 세션 차단, 비밀번호 복구와 기관 간 정보 차단 테스트.
7. 190시설 가운데 독립 교구 시설 등은 해당 관할 운영 주체에 연결. 공식 신청처와 실제 프로그램은 각 기관 확인 후에만 신자에게 공개.

## 6. 필수 QA
- CBCK 각 분류 결과 숫자가 실제 목록 총수와 정확히 같지 않으면 업로드 중지.
- 같은 수도회 본부·분원·회차 때문에 여러 관리번호가 자동 발급되지 않아야 함.
- 기관 A는 B의 시설/피정 운영 정보에 작성·삭제 권한 없음.
- 미승인/비활성 기관은 비밀번호/관리자 접속 기능 없음.
- 연계 미확인 피정의 집은 소속이 '검토 필요'로 표시되고 임의의 수도회에 자동 소속되지 않음.
- 관리번호·시설번호 중복 없음. 재수집해도 이미 예약된 번호가 변하지 않음.
- v0.2 공개 사이트 unchanged; 사용자 별도 승인 이전 v0.21 정식 공개 금지.

실제 프로젝트 연결 전 검토·검색·가입 승인 기능과 0004 마이그레이션을 추가했습니다. 최신 적용 순서·검증 수치·미완료 클라우드 작업은 [CBCK_PRELOAD_IMPLEMENTATION.md](CBCK_PRELOAD_IMPLEMENTATION.md)를 따릅니다. 2026-11-10 별도 개발 Supabase에 0001~0004와 비공개 후보 자료 등록을 완료했고 실제 DB에서 기관 간 격리를 확인했습니다. 운영 계정/비밀번호는 미발급입니다. CI는 이제 명부 원본/SQL 다운로드 자료를 게시하지 않고 집계만 표시합니다.
