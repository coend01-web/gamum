# 일상형 10문항 v2 — 구현 안내

기준 문서: `quiz-everyday-v2-spec.md` 전체. 참고: `retreat-taxonomy-and-quiz-v1.md`의 피정 범주·공고 출처. 작업 브랜치: `quiz-everyday-v2`. 기준 main: `d2cc0ce0dbf324a786a5023c3d87cf199c4edd6a`.

## 구현한 내용

- Q1~Q10의 문장·선택지·숨은 태그·가중치를 사양서와 동일하게 `assets/js/quiz-data.js`에 분리했습니다.
- `assets/js/recommendation.js`는 화면과 독립된 추천 계산입니다. 질문당 가중치 합을 1로 만들고, 필요·콘텐츠·진행 방식 축마다 정규화합니다. 직접 일치 3, 관련 일치 1, 약한 추론 0.5를 곱합니다. 음악→성령 전통, 걷기→프란치스코 전통의 자동 연결은 없습니다.
- 공식 자료의 특징과 답변의 실제 교집합으로만 사유를 만듭니다. 명시적인 관심 영성 선택은 별도 가산합니다. 특정 전통을 생활 취향으로 판정하는 유형 문구도 피했습니다. 기존 유형과 묵상은 서랍 호환을 위해 남겼습니다.
- 프로그램별 모든 회차에 먼저 필수조건을 적용하고, 그 후 점수를 매기고 프로그램 중복을 제거합니다. 0~3개만 표시합니다. 비슷한 점수(0.25 이내)에서만 기관·지역 중복을 소폭 조정합니다.
- Q9와 Q10은 기본적으로 선호입니다. 결과에서 기간·동행 필수 체크가 가능합니다. 프로그램 자체의 배타적 자격은 선호 점수로 무시하지 않습니다.
- 지역·가능한 시작/종료일·1인당 전체 예산·숙박 방식·연령 범위·인원·미성년 자녀·성별·대상·혼인·성소·신앙 단계·경험·정확한 선행 과정·관심 영성을 조절합니다. 개인 답변과 조건은 저장하지 않습니다.
- 유형 문장 → 추천 → 조건 조정 → 기존 위로·성경·성인·질문·기도 → 저장/공유 순서를 유지합니다.
- 질문 패널만 바꾸고 스크롤과 포커스를 유지합니다. 6개 선택지에 맞춘 일정한 영역을 사용합니다. 마지막 선택 후 ‘결과 보기’를 누릅니다. 이전·건너뛰기도 유지합니다.
- ‘오늘, 1분 머뭄’은 접기 장치를 없애 처음부터 마음 선택과 시작 버튼을 보여줍니다.

## 초기 검토본에서 추천이 0개였던 이유

기존 12개 프로그램·14개 회차는 **모두 가상 자료**이며 그대로 보존했습니다. 기존 자료에는 동행 허용·정확한 선행 자격 등이 없습니다. 제목이나 태그만으로 이 정보를 지어내지 않습니다. 따라서 이 자료들은 추천 엔진에서 ‘참가 대상 확인 필요’로 보류되며 일반 주제·날짜·지역 탐색에서는 계속 볼 수 있습니다.

실제 공고는 이번 작업에서 운영 데이터로 추가하지 않았습니다. 연구 문서의 공식 일정 목록은 현재 모집 가능·개별 신청 자격을 보장하지 않기 때문입니다. 조건을 넓혀도 자료 자체의 부족은 해결되지 않음을 결과 화면에 설명합니다. 추천 1~3개 출력은 **자동 테스트에서만 사용하는 완전한 가상 자격 자료**로 검사했습니다. 초기 검토본에는 이런 자격을 붙이지 않았습니다. 이후 사용자의 명시적 요청으로 별도 가상 시연 조건을 추가했습니다. 현재 버전은 `demo-catalog.js`에서 원본 복사본에만 조건을 붙여 0~3개를 추천합니다. 변경한 시연 조건과 테스트는 `QUIZ-V2-DEMO.md`를 참고하세요.

## 실제 등록 자료를 연결하는 방법

기존 프로그램·회차 구조는 보존합니다. 검증한 자료를 연결할 때 프로그램에 `recommendation`, 해당 회차에 `recommendation` 객체를 붙이면 어댑터가 인식합니다. 질문을 변경할 필요가 없습니다. `tests/recommendation-v2.mjs`가 스키마의 실행 예입니다.

프로그램의 recommendation:

- `demo`: 가상 여부. 실제 자료는 false.
- `taxonomy`: `purpose`, `tradition`, `format` 등 배열을 가진 객체. 확인된 복수 태그만 등록합니다. 새 전통도 기존 목적·방식 태그와 함께 연결 가능합니다.
- `requirements`: `complete`(공고의 자격 검토 완료), `minAge`, `maxAge`, `gender`, `roles`, `companies`, `marriedOnly`, `vocationOnly`, `faith`, `minParty`, `maxParty`, `prerequisites`.
- `complete:true`는 실제로 제한 항목을 모두 검토한 경우에만 사용합니다. 미등록을 ‘제한 없음’으로 바꾸지 않습니다. `companies`는 허용된 동행을 명시해야 합니다. 연령 제한이 있으면 사용자·동행 연령도 확인합니다.
- `source`: 공식 공고의 `url`, `verified`, `checkedAt`. 기관 이름·표시 대상은 기존 필드를 유지하거나 정확한 `organization`, `audience`로 제공할 수 있습니다.

회차의 recommendation:

- `demo`, `source`(프로그램과 별개인 실제 회차 공고 검증).
- `mode`: `daytime`, `residential`, `commuter`, `online` 중 확인된 값.
- `fee`, `feeUnit:'person'`, `feeComplete:true`: 추가 비용을 포함한 1인 전체 금액이 확인된 경우. 팀 단위 비용·미확인 추가비를 임의로 나누지 않습니다.
- `phone`, `applicationUrl`: 공식 문의·신청 경로. 실제 자료는 적어도 한 경로가 필요합니다.
- `status`, `checkedAt`, `remaining`: 모집 확인 근거. `open`만 쓰고 확인 시각이 없거나 15분보다 오래되면 ‘주최 측 확인 필요’. 종료·취소·접수 마감은 제외. 확인된 잔여석보다 많은 인원은 제외합니다.
- 정확한 `start`, `end`, `applicationStart`, `applicationEnd`, `region`, `place`, `capacity`는 회차 값으로 관리합니다. 이미 시작한 회차는 신규 추천하지 않습니다.

후보가 아예 없는 것과 자격 미확인, 조건 불일치를 분리합니다. 개인정보가 부족한 경우에도 통과시킨 것으로 안내하지 않습니다. 확인된 모집 상태도 참가 확정을 의미하지 않습니다.
