## 구현

`design/index.html`에 새 디자인을 독립 구현했습니다. 기존 `index.html`, `assets/`, `ops/`, `supabase/`는 변경하지 않았습니다. `legacy.html`은 기존 진입 화면과 바이트 단위로 같습니다. 기존 QR·후기·수도회 3단계 등록 시연과 이전 서랍은 연결 링크를 통해 그대로 사용할 수 있습니다.

- 고정 로고 「가뭄.」, 20개 첫 문장, PC 20개 + 모바일 전용 구도 20개 SVG, 80개 묵상 단계.
- 따뜻한 돌빛·아이보리·세이지, 로컬 명조/고딕, 1/2/5px 선의 역할 분리.
- `themes.json`으로 원고·색·출처 분리. `visuals/`에서 그래픽 개별 수정.
- 20개 셔플 방문 순서, 같은 탭에서 테마 유지, 새로고침 후 묵상 단계 복원.
- 네 가지 탐색을 같은 위치/위계로 유지. 주제, 즉시 지역 필터, 날짜·예산 검색.
- 기존 10문항 문구·숨은 태그·추천 엔진을 그대로 불러옴. 자격/동행/예산 엄격 확인 및 0~3개 추천 유지.
- 공식 승인 자료와 가상 시연을 명시적으로 전환. 기본은 승인 자료. DB 요청은 기존 `public_catalog` 읽기 전용 RPC 한 가지뿐.
- 운영실은 기존 v0.21 진입을 연결합니다. 이 디자인 작업에서 기관 로그인·MFA·DB 쓰기 검사를 새로 진행하지 않았습니다.

## 검사 결과

### 자동 검사

`npm test` 기존 전체 검사 통과: 기존 화면, 추천 시나리오, 가상 데이터, CSV/반복 회차, MFA, 로컬 PostgreSQL 권한·기관 격리, Edge handler 및 명부 검사. 기존 테스트의 로컬 DB/Auth 모의 실행을 실제 운영 보안 검사로 표현하지 않습니다.

`node tests/design-spaces.mjs` 통과:
- 20개 테마 및 80개 서로 다른 단계, 공식 성경 링크·검수 표시.
- 40개 고유 SVG, 총 117,809 bytes, 외부 이미지/스크립트 없음.
- 테마 바탕의 본문·보조·강조 글자 명도 대비 4.5:1 이상.
- 200회 방문의 20개 균등 순환, 연속 중복 방지, 동일 방문 테마 유지.
- 80개 진행 저장/복원, 손상·차단된 저장소의 안전한 폴백.
- 기존 진입 파일 보존, 읽기 전용 공개 설정, 움직임 줄이기 CSS 및 초점 표시.

### 실제 브라우저

- 360×844, 390×844, 768×844, 1440×1050: 가로 넘침 없음, 적합한 PC/모바일 SVG 로딩.
- 360/390에서 네 가지 탐색 하단 약 786px. 작은 높이에서는 자연스러운 세로 스크롤이 필요합니다.
- 360×800 및 390×844에서 10문항 모두 직접 클릭: 질문 상단 189.8px 고정, 스크롤 0 유지, 선택지 최하단 최대 670.8px.
- PC에서도 10문항 완료 및 추천 3개 확인.
- 쉼/말씀/화해/식별/찬양/가족의 60개 답변 실제 클릭, 6개 시나리오의 첫 추천 모두 다름.
- 예산 0원으로 조건 조정 시 추천 0개. 빈 결과를 가짜로 채우지 않음.
- 20개 테마의 80단계 실제 클릭, 원고 및 제목/그림 연결 확인. 성경 문장의 원문 줄바꿈도 보존.
- 묵상 2단계에서 새로고침 후 같은 단계 유지.
- 주제 ‘쉼’ 4회차, 지역 ‘부산’ 1회차, 2027-01-01 이후 날짜 검색 1회차.
- 피정/묵상 서랍 저장 및 표시, 20개 갤러리 및 80단계 원고 펼치기.
- 수도회 기존 등록 시연 1→2→3단계, 기존 QR 종료 후 후기 화면 확인.
- 본문 바로가기와 Enter 키 묵상 진행, 초점 표시. 브라우저 콘솔 오류 없음.

검사 중 수정: 본문 바로가기를 누르면 잘못된 화면으로 이동하는 문제, 주제 검색 후 지역 검색에서 보이지 않는 주제 조건이 남는 문제, 모바일 SVG의 주요 오브젝트 잘림을 수정했습니다.

## 남은 검토와 범위

- 원고의 신학·표현 최종 편집 검수 및 가톨릭 새번역 사용 승인 범위 확인은 정식 공개 전 진행합니다. `CAMUM_SCRIPTURE_SOURCES.md`에 20개 출처와 확인 사항을 기록했습니다.
- 승인된 실제 피정이 현재 없다면 빈 화면 안내가 정상입니다. 체험은 ‘가상 시연 데이터’를 선택합니다. 실제 기관의 조건을 임의 생성하지 않았습니다.
- 새 서랍은 디자인 검토판 전용 브라우저 저장소입니다. 기존 서랍의 데이터는 삭제하지 않고 별도 링크에서 그대로 접근합니다. 실제 배포 승인 시 통합 저장소 전환 여부를 결정합니다.
- 실물 휴대폰·VoiceOver 전체 읽기 검사는 별도이며, 이번 검증은 브라우저의 실제 화면 크기 변경과 키보드/DOM 검사입니다.
- 공개 홈페이지 반영, main 병합, Supabase 데이터 변경은 수행하지 않았습니다.

## 로컬에서 확인

`node scripts/serve-design.mjs` 실행 후 `http://127.0.0.1:8773/design/index.html`을 엽니다. 미리보기 패키지는 `node scripts/package-design.mjs <저장소 밖 별도 폴더>`로 필요한 브라우저 자산만 복사합니다. private/SQL/비밀키/Git 기록은 패키지에 포함하지 않습니다.
