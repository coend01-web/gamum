# CAMUM v0.21 구현·검증 현황

상태: **작업 브랜치의 실제 코드 구현 및 로컬 검사. 아직 정식 운영·클라우드 보안 검증 완료 아님.**
기준: 2026-11-09 확인한 `V021_BUILD_SPEC.md`, `V021_CODEX_START.md`의 최신 내용. 작업 도중 추가된 기관 공용 계정·장기 확장 요구도 반영했습니다.

`feature/v0.21-convent-ops`만 변경합니다. main/v0.2 공개 사이트·index.html·기존 데이터·10문항·묵상·서랍·수도회 시연·QR 시연은 보존합니다.

## 구현

### 기관 계정과 중앙관리

- 기관당 고유 관리번호(`CAM-000001` 형식) 하나와 공용 비밀번호 하나. 번호는 DB 시퀀스와 UNIQUE 제약으로 발급, 담당자 변경 후에도 고정.
- 중앙관리자가 기관 등록→공식 연락처로 검증→승인→일회용 초기설정 링크 발급. 비밀번호는 기관 담당자가 설정하며 중앙관리자에게 표시하지 않습니다. 담당자별 회원 가입은 필수가 아닙니다.
- Supabase Auth가 비밀번호를 처리합니다. `organization_credentials`에는 기관/Auth 사용자 연결과 계정 상태만 저장하며 비밀번호 원문·해시를 중복 저장하지 않습니다.
- `institution-auth` Edge Function이 관리번호 로그인, 초기설정, 비밀번호 변경, 기관 확인 후 복구를 처리합니다. 서버 전용 키와 IP 해시용 salt는 서버 환경변수에만 둡니다.
- 비밀번호 변경 전 기존 비밀번호 재확인. 변경 시 DB의 허용 세션을 모두 제거하여 **이미 발급된 JWT도 RLS 접근 불가**. Auth 세션 존재 확인, 24시간 앱 세션 수명, 인증 제공자에서 직접 바꾼 비밀번호/이메일도 트리거로 즉시 차단. 동시 변경은 세션·계정 상태를 검사해 한 작업만 진행합니다.
- 관리번호만으로 비밀번호 재설정 불가. 복구 요청→중앙관리자가 기존 공식 연락처로 확인→30분 일회용 링크→새 비밀번호. 토큰은 DB에 해시만 저장하며 재사용 불가.
- 중앙관리자는 별도 개인 계정과 **MFA(AAL2)** 필수. DB와 Edge에서 모두 검사. 첫 중앙관리자 지정은 프로젝트 소유자가 수행해야 합니다.
- 로그인/복구 시도 제한, 15분 잠금, 중앙·기관 보안 알림, 기관별 변경 시각·세션 식별자 기록. 원문 IP·비밀번호·토큰을 애플리케이션 로그에 남기지 않습니다.
- 공유계정으로 어느 개인이 수정했는지 알 수 없으며, 비밀번호를 바꾸지 않으면 이전 담당자가 접근할 수 있음을 인수인계 화면에 명시.
- 기존 `organization_members`/초대 구조는 후속 선택적 개인 권한 확장용으로 내부에 보존했지만 v0.21 기본 화면에서 개인 가입·초대를 요구하지 않습니다.

### 프로그램·회차 운영

- 여러 피정의 집, 전체 프로그램 다건 등록·수정·복제·보관, 개별 회차 수정·조기마감.
- 프로그램과 실제 날짜/비용/정원/모집 기간/진행 방식/신청 링크를 가진 회차를 분리.
- 주기적 반복 회차 생성, CSV 검사→미리보기→오류 수정→확인 저장. 한 요청은 200개까지이며 전체 프로그램/회차 수 제한이 아닙니다.
- 서버 트랜잭션으로 전체 저장 또는 전체 취소. 같은 프로그램/시작일 중복 방지. version으로 동시 수정 충돌 감지.
- 기관 승인 + 프로그램 검토 승인 후 공개. 프로그램 본문·참가 조건·장소가 바뀌면 초안으로 돌아가 재검토. 한 회차의 마감은 다른 회차에 영향 없음.
- 알 수 없는 자격을 확인된 조건으로 게시하지 못하도록 서버 검증. 비정상 비용·날짜·자격 자료 차단. 잔여석은 근거와 확인 시각이 있을 때만 표시하며 실시간으로 주장하지 않습니다.

### 신자 화면과 후기

- `ops/catalog.html`에서 승인된 자료만 네 가지 입구·주제/날짜/지역 검색·기존 일상형 10문항 추천에 반영. 참가 자격과 선호를 분리해 0~3개만 추천.
- 결과 순서: 유형·한 줄 설명 → 추천 → 조건 조정 → 위로·가톨릭 새번역 링크·성인·묵상·기도. 1분 머뭄 기본 펼침, 기기별 서랍 유지.
- 실제 자료와 기존 가상 시연 카탈로그는 섞지 않음. 가상 로컬 검사 화면은 항상 가상으로 표시하며 신청 링크를 활성화하지 않음.
- 일회용 현장 확인 QR→로그인한 참가자의 후기→중복 차단→중앙관리자 개인정보 검토 후 익명 공개. 담당자가 직접 출석을 확인해 참가자 1명에게 코드 1개를 전달합니다. QR만으로 물리적 출석이 자동 증명되는 것은 아닙니다.
- 관심 프로그램 변경 알림은 계정의 **내 알림**에 저장. 이메일/SMS 자동 발송은 연결하지 않았습니다.
- 공식 신청처 이동·연락처 안내. 신청/입금/환불/참가 확정은 각 수도회에서 진행.

### 이후 확장

`organizations.organization_type`과 확장 가능한 조직 분류 테이블로 수도회·피정 운영기관·교구·본당·사도직·생활성가 단체를 구분합니다. 기관/장소/프로그램/회차의 UUID를 분리하여 이후 사제·강사·음악팀과 다대다 관계 테이블을 추가할 수 있습니다. 피정 카탈로그는 `catalog_kind=retreat`만 허용합니다. 공연/문화행사/성지순례 광고는 추천에 섞지 않으며, 개인 사제·가수에게 기관 공용 계정을 강제하지 않습니다. 사제 디렉터리나 공연 예약 기능 자체는 이번 범위가 아닙니다.

## 코드 위치

- `ops/`: 운영실·신자 카탈로그·Auth 연결·CSV/반복 검사·공통 스타일.
- `supabase/migrations/202611080001_convent_ops.sql`: 운영 테이블, RLS, 승인/저장/공개/후기/알림 RPC.
- `supabase/migrations/202611090002_institution_credentials.sql`: 기관 관리번호·공용 계정·MFA·세션 차단·복구·시도 제한.
- `supabase/functions/institution-auth/index.ts`: 실제 Supabase Auth를 사용하는 서버 로그인/발급/복구/인수인계 처리.
- `supabase/config.toml`: Edge 공개 로그인 진입점 설정. JWT 없는 로그인/복구만 허용하고 인증된 작업은 코드 안에서 `getUser`와 DB의 MFA/세션을 확인합니다.
- `tests/ops-db.mjs`, `tests/ops-edge.mjs`: 실제 PostgreSQL 엔진 + 명시적인 가상 Auth 검사.
- `tests/ops-hosted.mjs`: 별도 개발 Supabase에서 실행할 실제 Auth/Edge/RLS 검사. **아직 실행하지 않음.**

## 확인한 범위와 남은 범위

로컬 SQL은 PGlite PostgreSQL 엔진에 Supabase `auth.uid()`/`auth.jwt()`/Auth 테이블 인터페이스를 모사해 실행합니다. Edge 검사는 같은 SQL과 **가상 Auth 제공자**로 실행합니다. 클라우드 인증·JWT 설정을 검증했다고 표현하지 않습니다.

- 기존 v0.2 회귀, 추천 176개 항목, 서로 다른 6개 답변 조합 통과.
- CSV/반복/조건/승인 카탈로그 연결 등 새 순수 로직 23개 검사 통과.
- RLS/기관 격리/승인·MFA 우회/시도 제한/인수인계/중복/원자성/동시 수정/후기/알림 등 SQL 68개 검사 통과. 기관 번호 300개 발급 중 중복 없음.
- Edge 가상 Auth 검사 18개: 최초 계정 발급, 번호 로그인, 옛 비밀번호 거절, 옛 JWT 차단, 검증 후 복구, 토큰 재사용 방지, 비허용 출처 차단 등.
- 브라우저: 프로그램 2개·총 43회차를 생성(반복 40개, CSV 2개 포함), 새로고침 유지, 회차 한 개만 조기마감, 승인 후 검색/추천, 지역/날짜/주제, 서랍, 1분 머뭄, 기관 B의 A 자료 비노출 확인.
- 360/390/768/1280px에서 각 10문항 직접 클릭, 질문 위치 유지·선택지 화면 내 표시·가로 넘침 없음. 최신 기관 로그인·인수인계 화면도 네 폭에서 검사.
- 실제 스마트폰, 실제 수도회 담당자, 실제 클라우드 Auth/Edge/메일/복구 환경은 아직 미검증.

**정식 배포 차단 조건**: 개발 프로젝트 연결 후 실제 MFA/로그인/비밀번호 변경/기존 세션 폐기/기관 복구/RLS 공격 시나리오, 실제 담당자·실기기 E2E, 외부 공식 신청처, 클라우드 백업/복구 리허설, 클라우드 시도 제한·남용 방지·네트워크 프록시 설정, 개인정보 보존/삭제 정책을 검증해야 합니다. 그 후 사용자가 별도로 승인해야 main에 반영할 수 있습니다.

Storage 사진 업로드는 구현하지 않았으며 허가 없는 사진을 게시하지 않습니다. 공개 사이트는 현재 v0.2 그대로입니다.

## 지금 필요한 사용자 조치 — 첫 단계

https://supabase.com/dashboard 를 열어 **로그인**해 주세요. 로그인 뒤 **New project** 버튼이 보이는지 알려주시면 다음 버튼부터 한 단계씩 안내합니다. 이미 개발 프로젝트가 있으면 새로 만들지 않고 그 프로젝트를 확인합니다. 비밀번호·secret key·DB 암호는 채팅이나 GitHub에 보내지 마세요.

이후 별도 개발 프로젝트에서 진행할 작업:
1. 두 SQL 파일을 파일명 순서대로 적용.
2. `institution-auth` Edge Function 개발 배포. 서버 환경에 `CAMUM_ALLOWED_ORIGINS`(개발 미리보기의 정확한 origin 목록), 충분히 긴 무작위 `CAMUM_RATE_SALT` 설정. 서버 전용 Supabase 키는 Edge 환경에서만 사용.
3. 프로젝트 소유자가 중앙관리자 테스트 계정의 UUID를 `camum_private.operators`에 등록. 운영실의 중앙관리 로그인에서 인증 앱 MFA 설정.
4. 운영실 연결 화면에 Project URL과 `sb_publishable_` 공개 키만 입력.
5. 가상 개발 기관 A/B 발급, 기관 초기 비밀번호 설정, 실제 Auth/Edge/RLS/E2E 검사.
6. Auth 직접 가입/이메일 변경/재인증/리디렉션/세션 설정·rate limit·남용 대응을 개발 환경에서 확인. 검증되지 않은 설정으로 정식 배포하지 않음.

## 로컬 미리보기

Node.js 22.13 이상에서:

```sh
npm ci --ignore-scripts
npm run build:ops
npm test
node scripts/serve-ops-test.mjs
```

- 운영실: http://127.0.0.1:8771/ops/index.html?sandbox=1
- 승인 카탈로그: http://127.0.0.1:8771/ops/catalog.html?sandbox=1
- 실제 개발 DB 연결 화면: http://127.0.0.1:8771/ops/index.html

이 컴퓨터에서만 열리는 주소입니다. `?sandbox=1`은 실제 비밀번호 인증이 아닌 **가상 테스트 버튼**과 메모리 PostgreSQL을 사용합니다. A 기관 테스트 버튼으로 운영 화면을 볼 수 있습니다. 서버 재시작 시 가상 데이터는 초기화됩니다. 초기에는 기관/프로그램이 승인 전이므로 카탈로그가 비어 있습니다. 중앙관리자 테스트→기관 승인, A 기관 테스트→공개 검토 요청, 중앙관리자 테스트→프로그램 승인 순서로 확인합니다.

정식 클라우드 연결은 sandbox 없이 사용합니다. 인터넷 주소를 임의로 공개하거나 main으로 배포하지 않았습니다. 테스트 서버와 가상 Auth 코드는 정식 서비스에 배포하지 않습니다.

## 복구

기존 v0.2는 기존 백업 태그·GitHub 백업 브랜치와 로컬 `outputs/gamum-before-v0.21.bundle`로 보존했습니다. 운영 DB는 Git에 포함되지 않습니다. 실제 프로젝트 준비 후 별도 DB 백업을 새 개발 DB에 복원하는 리허설이 필요합니다. 개인정보가 든 DB 덤프는 GitHub에 올리지 않습니다.

호스팅 검사: Git 밖 개인 환경 파일에 개발 URL·공개 키·개발 origin·중앙 테스트 계정·이번 MFA 코드를 설정해 `node --env-file=/개인경로/개발검사.env tests/ops-hosted.mjs` 실행. `CAMUM_ALLOW_DEVELOPMENT_WRITES=yes`가 필요합니다. 검사 기관은 종료 시 suspended로 숨깁니다. 실제 운영 DB에는 실행하지 않습니다.

참고: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [서버 함수](https://supabase.com/docs/guides/database/functions), [세션](https://supabase.com/docs/guides/auth/sessions), [MFA](https://supabase.com/docs/guides/auth/auth-mfa).
